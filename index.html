    📖 FAQ & Troubleshooting Guide

    Q: What does this dashboard actually do?
    It is a zero-trust, read-only C2 status monitor. It issues lightweight GET requests against the target daemon (/ and /api/tags) to report link state, round-trip latency, and installed model inventory. No prompts, writes, or state are ever sent — there is no chat surface and no backend execution logic on this page.
    Q: How do I bring the target daemon online for monitoring?
    On the target machine (192.168.1.236), launch PowerShell and initialize Ollama with CORS permissions enabled:
    $env:OLLAMA_ORIGINS="*"
    ollama serve
    Once active, the daemon status above will turn green and the model inventory will populate automatically.
    Q: Why is the Daemon Status showing offline?
    Browsers block local scripts from talking to background ports unless the origin environment variable is open. Make sure ollama serve is running in your background terminal.
    Q: Why use the local IP address (192.168.1.236) instead of localhost?
    Targeting your machine's physical network IP adapter guarantees correct socket resolution across local boundary policies without triggering loopback blockages in static HTML previews.
    Q: What is the independent session counter?
    The SESSION ID readout in the header is a self-contained tick loop that increments once per second from zero on every page load. It is not tied to the endpoint checker or any other component — it simply measures how long this monitoring session has been alive.
    Q: Is this node completely private and offline?
    Yes. All execution loops run locally on hardware without routing telemetry or state data through external cloud gateways.
